Getting started 🚀¶

Minimum requirements¶

Requirement Minimum version
Java 17
Gradle 8.11
Kotlin 2.2.0
Android Gradle Plugin 8.7.3 (for Android projects)

1. Add the Plugin Dependency¶

Go to your build-logic folder, in the build-logic/build.gradle.kts, add the following dependency:

implementation("io.github.codandotv:popcornguineapig:<version>")

2. Apply the Plugin¶

You can use the parent plugin to define all your rules in a centralized place.

2.1. Parent plugin¶

Starting with version v3.1.0, we introduced support for a parent plugin, enabling developers to define all project rules in a centralized location.

Let’s create a plugin that will be applied to the root build.gradle file of our project:

// build-logic/popcorngp-setup-plugin.gradle.kts
plugins {
  ...
  id("io.github.codandotv.popcorngpparent")
}

Configure All Your Architecture Rules¶

Now, we can specify in a single place all the rules that we want to apply to our project.

// build-logic/popcorngp-setup-plugin.gradle.kts
popcornGuineapigParentConfig {
    type = ProjectType.KMP

    children = listOf(
        PopcornChildConfiguration(
            moduleNameRegex = ":util:[a-z]+",
            rules = listOf(
                NoDependencyRule(),
            ),
        ),
        PopcornChildConfiguration(
            moduleNameRegex = ":feature:[a-z]+",
            rules = listOf(
                DoNotWithRule(
                    notWith = listOf("data"),
                ),
            ),
        ),
        // ... more children
    )
}

Don’t forget to apply the plugin to the root build.gradle file:

// root/build.gradle.kts
plugins {
    id("popcorngp-setup-plugin")
    ...
}

Run the task¶

./gradlew popcornParent

Evaluating only selected modules¶

Module selection available >= 3.3.0

Starting from version 3.3.0, popcornParent accepts --modules to evaluate only selected modules.

For large builds, evaluate only the modules affected by a change by passing their Gradle project paths:

./gradlew popcornParent --modules=":app,:core:network"
  • Paths are comma-separated; the leading : is optional (app becomes :app).
  • Duplicate and blank entries are ignored.
  • Unknown project paths fail the build before any analysis starts.
  • Selected modules that don’t match any PopcornChildConfiguration are skipped with a warning.
  • With -PerrorReportEnabled, the error report contains only the evaluated modules.
  • Omit --modules to keep evaluating every configured module.

The option reduces dependency inspection and rule evaluation for unselected modules, but Gradle still configures the whole build. If your project uses the configuration cache, combine it with --no-configuration-cache:

./gradlew popcornParent --modules=":app,:core:network" --no-configuration-cache

Metrics task

--modules applies to popcornParent only. popcornModuleMetrics must analyze the full graph to compute accurate FanIn/FanOut values.

For Gradle projects with Cache enabled for the Configuration Phase

In case your project has cache enabled for the Gradle configuration phase, you need to disable that for popcorngp. So your command should be: 

./gradlew popcornParent --no-configuration-cache

2.2. AI-Assisted Setup 🤖¶

AI skill available >= 3.2.3

Starting from version 3.2.3, PopcornGP ships with an embedded AI skill file that helps AI coding tools configure the plugin automatically.

To install the skill file in your project, run:

./gradlew installPopcornSkill

This creates a SKILL.md file that AI tools (OpenCode, Claude Code, Cursor) can use. See the AI Skill Installation page for custom destinations and details.
